# 科研库规则

## 主库与叶级子库
主库用于导航、共享知识和全库索引。一个独立研究目标对应一个子库，子库可被分类文件夹组织，子库内部不再嵌套 Vault。项目内每次实验用记录或普通目录表示。
完整目录蓝图位于 `规则与模板/项目文件夹模板/标准科研项目`，由 `template.json` 描述目录与文件模板。新建项目读取蓝图，不能把蓝图当作真实 Vault。已有项目不随模板变更自动迁移。
子库目录名/注册名和项目编号均全局唯一，避免 URI 歧义。项目编号采用字母开头的字母、数字、下划线和连字符，大小写不同也视为重复。

## 笔记与外部物料
保存文献解读、设计、配置、实验记录、可读日志、指标、关键图表与物料定位信息。代码、原始数据集、权重留在外部。每条实验记录尽量关联运行编号、代码提交、数据版本及划分、配置、随机种子和证据位置。

## 科研可靠性
医学影像与脑机接口评估应说明患者/受试者级数据划分、预处理、数据泄漏检查、基线与重复实验。没有证据的结果不得写成事实。已有结论以追加修订追踪变化。

## 属性
统一采用 `type`、`project_id`、`status`、`created`。实验加 `run_id`、`code_commit`、`dataset_version`；文献加 `citekey`、`year`、`source`；结果加 `metric`、`value`、`unit`；交接加 `handoff_id`、`received`。
插入模板后替换占位，项目编号不能随项目改名而变化。共享知识的 `project_id` 留空。
项目状态：planning / active / paused / writing / complete / archived；示例为 example。
交接状态：received / organizing / needs-info / complete。状态存储在日志属性中，Bases 展示这些属性。

## 链接
项目文件名以稳定项目编号开头，例如 `P001-实验-R001.md`。Wiki 链接使用唯一文件名，主库和子库都能找到项目内目标。子库指向共享知识采用主库 URI；URI 目标设备须按 `vault.json` 中的主库名称登记仓库。
项目移动后需更新同步配置目录；项目改名后也需更新子库打开 URI。普通 Obsidian 改名操作不保证更新所有跨库 URI。

## 同步
仅主库同步，研究时保持主库打开。可共享配置与项目资产应同步；窗口布局和同步哈希等运行时索引保持本地。子库独立同步禁止启用。多端同时访问不等于同一文件无冲突协同编辑。
无凭据的子库配置目录清单为 `规则与模板/子库同步目录.json`；每台设备需要独立应用清单并重新完整拉取子库配置，不能指望本机插件 data.json 自动同步到另一设备。
附件优先遵循当前 custom-attachment-location 插件的笔记旁同名目录策略；`80 附件` 只是核心备用目录。不要在不了解跨库引用时使用批量附件清理。
