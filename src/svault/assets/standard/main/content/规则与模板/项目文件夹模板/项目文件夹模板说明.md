# 项目文件夹模板说明

`标准科研项目` 是完整项目目录蓝图，包含目录清单、项目主页、项目 Agent 规则和四个 Bases 文件模板；它与单篇笔记模板用途不同。
新建工具直接读取这份蓝图。修改蓝图只影响后续新项目，不覆盖已有项目。

```text
项目名称/                      ← 创建后成为叶级 Vault
├── .obsidian/                 ← 工具继承主库配置，关闭独立同步
├── 项目.json                  ← 稳定项目编号与模板版本
├── AGENTS.md                  ← 由 AGENTS.md.template 生成
├── 项目编号-项目主页.md
├── 00 收件箱/
├── 01 文献/
├── 02 研究设计/
├── 03 实验记录/
├── 04 结果与图表/
├── 05 总结与写作/
├── 06 科研日志/
├── 07 会议与决策/
├── 08 交接记录/
│   └── 原始材料/
├── 80 附件/
├── 90 模板/                   ← 从主库笔记模板生成，填入项目编号
└── 95 索引/                   ← 文献、实验、结果、交接 Bases
```

## 如何使用
按 [[新建项目]] 操作；Agent 同样使用新建工具，不手动拼装目录。
不要把 `标准科研项目` 直接打开成 Vault。蓝图不含真正的 `.obsidian` 或有效项目主页，避免被误判为科研项目。
`.template` 文件必须先替换项目编号、名称、日期、分类和 URI；仅复制目录不能得到可用子库。
`template.json` 的 `directories` 是空目录的权威清单；目录即使没有文件，也会在新建时生成。模板说明和目录占位不是研究证据。

## 修改边界
`template.json` 定义目录、文件模板映射、笔记模板来源与生成项；主页和 AGENTS 的正文分别编辑对应 `.template` 文件。
当前标准结构的科研规则、索引过滤及叶级边界不能被无意删除。更改目录或属性规范时，同步修改说明、生成校验与规则，再运行生成测试。
已有项目结构调整需要单独迁移；不重新运行主库初始化，也不覆盖项目已有内容。
